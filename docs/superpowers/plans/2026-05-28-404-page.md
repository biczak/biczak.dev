## Task 1: E2E test + 404 page (TDD cycle)

**Files:**
- Create: `tests/e2e/404.spec.ts`

- [ ] **Step 1: Write the failing E2E test**

Create `tests/e2e/404.spec.ts`:

```ts
import { test, expect } from '@playwright/test';

test.describe('404 page', () => {
  test('returns HTTP 404 for non-existent routes', async ({ page }) => {
    const response = await page.goto('/this-route-does-not-exist');
    expect(response?.status()).toBe(404);
  });

  test('renders the 404 page with H1 and three recovery links', async ({ page }) => {
    await page.goto('/this-route-does-not-exist');
    await expect(page.getByRole('heading', { level: 1 })).toContainText(
      "This route doesn't exist"
    );
    const main = page.locator('main');
    await expect(
      main.getByRole('link', { name: '[ home ]', exact: true })
    ).toHaveAttribute('href', '/');
    await expect(
      main.getByRole('link', { name: '[ tools ]', exact: true })
    ).toHaveAttribute('href', '/tools');
    await expect(
      main.getByRole('link', { name: '[ contact ]', exact: true })
    ).toHaveAttribute('href', '/#contact');
  });
});
```

- [ ] **Step 2: Run the test, verify it fails**

Run:
```bash
pnpm build && pnpm e2e --project=chromium tests/e2e/404.spec.ts
```

Expected: both tests FAIL. The first because Astro preview server returns 200 for unknown routes (no 404.html in build yet). The second because there is no H1 with "This route doesn't exist" text.

## Task 2: Configure Cloudflare Pages to return 404 status in production

**Why this is needed:** Astro preview already returns 404 for unmatched routes — the test in Task 1 verifies that, and it'll pass in CI. But Cloudflare Pages' production behavior is different: without an explicit `_redirects` rule, CF serves `index.html` with HTTP 200 for unmatched routes. This task fixes the production behavior, which is the actual bug the spec addresses. There's no CI test for this — verification happens against the production URL post-deploy.

**Files:**
- Create: `public/_redirects`

- [ ] **Step 1: Create `public/_redirects`**

Create `public/_redirects` with exactly one line (no trailing comment, no leading whitespace):

```
/* /404.html 404
```

Format: `<from-pattern> <to-path> <status-code>`. The `/*` matches any path that isn't already a real file in `dist/`; `/404.html` is the file to serve; `404` overrides the default 200 status.

- [ ] **Step 2: Verify the file appears in build output**

Run:
```bash
pnpm build
```

Then verify:
```bash
ls dist/_redirects
```

Expected: file exists at `dist/_redirects`. Astro copies everything in `public/` to `dist/` during build, so this should Just Work. Cloudflare Pages reads `dist/_redirects` during deploy and applies rules at the edge.

- [ ] **Step 3: Commit**

```bash
git add public/_redirects
git commit -m "fix(deploy): return HTTP 404 status for missing routes"
```
